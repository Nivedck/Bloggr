BLOGGR — FINAL SYSTEM DESIGN & API ↔ UI INTEGRATION MAP
========================================================

1. PROJECT OVERVIEW
-------------------

Project Name:
Bloggr

Purpose:
A web-based blogging platform for a college community where students
and teachers can publish, discover, read, and interact with articles.

User Roles:
- user
- admin

There is exactly one admin account.

Technology Stack:
- Frontend: HTML + CSS + Vanilla JavaScript
- Backend: Node.js + Express.js
- Database: MongoDB
- ODM: Mongoose
- Authentication: Session-based authentication
- Password Security: bcrypt

4. DATABASE COLLECTIONS
-----------------------

users
------
_id
name
email
password
bio
role
createdAt
updatedAt

Constraints:
- email must be unique
- password is hashed
- role = user | admin
- new registrations always receive role = user
- users cannot change their own role


blogs
-----
_id
title
content
author
status
tags[]
upvoteCount
downvoteCount
commentCount
createdAt
updatedAt

Constraints:
- author references User
- status = draft | published
- tags are stored as an embedded array
- vote/comment counts are cached on Blog
- actual votes/comments are stored separately


comments
--------
_id
blog
author
content
parentComment
createdAt
updatedAt

Constraints:
- blog references Blog
- author references User
- parentComment references Comment or null
- only single-level replies are allowed


votes
-----
_id
user
blog
type
createdAt

Constraints:
- user references User
- blog references Blog
- type = upvote | downvote
- one active vote per user per blog
- unique compound index on (user, blog)


reports
-------
_id
reporter
targetType
target
reason
description
status
createdAt
updatedAt

Constraints:
- reporter references User
- targetType = blog | comment
- target references Blog or Comment
- reason = spam | harassment | hate | misinformation |
           inappropriate | other
- status = pending | reviewed | resolved | rejected
- backend verifies that target exists and matches targetType


5. DATABASE RELATIONSHIPS
-------------------------

1 User  -> N Blogs
1 User  -> N Comments
1 User  -> N Votes
1 User  -> N Reports

1 Blog  -> N Comments
1 Blog  -> N Votes
1 Blog  -> N Reports

1 Comment -> N Replies
           (single level only)

User <-> Blog
Many-to-many relationship through Vote.


6. DATABASE INDEXES
-------------------

users:
- unique index on email

blogs:
- index for published blogs + createdAt
- text index on title, content and tags

comments:
- index on blog
- optionally createdAt for ordering/pagination

votes:
- unique compound index on user + blog

reports:
- index on status
- optionally compound index on targetType + target


7. BLOG DELETION / CASCADE
--------------------------

When a blog is deleted:

Delete associated comments
Delete associated votes
Delete reports targeting the blog
Delete the blog

Preferred implementation:

Admin/User authorized to delete
        |
        v
Database transaction
        |
        +-- Delete comments
        +-- Delete votes
        +-- Delete reports
        +-- Delete blog
        |
        v
Commit transaction

36. HTTP STATUS CODES
---------------------

200  OK
201  Created
204  No Content
400  Bad Request
401  Unauthorized
403  Forbidden
404  Not Found
409  Conflict
422  Validation Error
500  Internal Server Error


401:
User is not authenticated.

403:
User is authenticated but does not have permission.

404:
Requested resource/route does not exist.

409:
Conflict such as duplicate email.

422:
Input failed validation.

500:
Unexpected server-side error.


37. VALIDATION PRINCIPLE
------------------------

Frontend validation:
- Improves user experience

38. SECURITY DESIGN
-------------------

Authentication:
- Session-based authentication
- Secure cookies

Password:
- bcrypt hashing
- Never store plaintext passwords

Authorization:
- Ownership checks
- Admin role checks

Cookies:
- HttpOnly
- Secure in production
- SameSite

Content:
- Sanitize user-generated HTML
- Prevent XSS

MongoDB:
- Validate ObjectIds
- Validate input types
- Restrict query fields/operators

CSRF:
- Protect state-changing requests

Rate limiting:
- Login
- Registration
- Reports
- Voting
- Comments

Environment:
- Secrets stored in .env
- .env excluded from Git

Production:
- HTTPS
